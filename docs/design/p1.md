# P1: Combination editing and macro bundle

Status: confirmed and implemented; hardware verification remains pending.

## Scope and source

- Extend the offline YAML build with readable combinations and a separate Launcher macro import file. Native transport and device/layer nicknames are excluded.
- Use source `version: 2`; migrate the current source and fixtures deliberately. Backward compatibility with source v1 is not required. Launcher keymap export remains version 2.
- Keep layers, combinations, and optional macros in the same authoritative `keymap.yaml`.
- Preserve the current user bindings and raw data. Initially add only the gateway combination, not invented macro definitions or triggers.
- Continue using the checked-in JSON Schema for standalone validation and build-time validation, with semantic checks during build.

## Combinations

Move records from `preserved.combinations` to a top-level `combinations` list. Each entry is readable or wraps an exact Launcher record in `raw`.

```yaml
combinations:
  - index: 0
    buttons: ["03", "04"]
    raw_layer: 0
    timeout: 200
    tap: {to: 0}
    hold: none
    name: Gateway
```

- Require explicit index, timeout, tap, hold, buttons, and exactly one of `layer` or `raw_layer`. Name is optional.
- `layer: 0..7` maps visible layers to raw 1..8. `raw_layer: 0..255` preserves the exact packet field.
- Do not offer an `all` shorthand: raw layer 0 is Launcher's observed creation value, not a verified wildcard. The gateway combination is intended to work from every layer; this requires a device test.
- Timeout 200 is the observed Launcher default; its units remain unverified.
- Reuse ordinary action syntax for tap and hold; do not support nested tap/hold bindings.
- Enforce 2–4 distinct drawn buttons, excluding the exact column set `[0,1,2,3]`. Reject momentary-layer tap actions and the established both-actions-mouse restriction.
- Raw records bypass UI-specific restrictions and retain extra fields and exact values, but still obey structural/range checks and global uniqueness.
- Reject duplicate slot indexes and duplicate member masks across all records, irrespective of button order, layer, or name. Maximum 30 records.
- Launcher names are shared by member-button set. Keep `preserved.combination_names` for raw/orphan entries; merge readable names without silently overwriting a conflicting preserved name.

## Macros

```yaml
macros:
  slot_count: 16 # Example only, not a verified Nape capacity.
  capacity_bytes: 1024 # Optional; supply only a verified limit.
  slots:
    - index: 0
      name: Example
      events:
        - tap: LG(A)
        - delay_ms: 200
        - text: "Hello"
```

- Require explicit slot count. Do not infer firmware capacity from the 16-entry trigger palette. Use explicit, unique slot indexes; names are optional.
- Pad unlisted slots with empty bodies and empty names. Submitting the generated bundle replaces the whole buffer, including those empty slots.
- Verify macro trigger references against definitions. Permit top-level `external_macros: [0, 1]` only without a macro bundle; fail rather than risk erasing externally managed bodies when generating a bundle.
- Readable events: `tap`, `down`, `up`, `delay_ms`, `text`. Use a pinned, verified macro-byte mapping, separate from the general 16-bit binding compiler.
- Lower tap to explicit down/up pairs. Support existing modifier-expression syntax for tap by ordered presses and reverse-order releases. Down/up accept individual representable keys only.
- Reject repeated presses, unmatched releases, final held keys, and taps conflicting with already-held keys in readable sequences. Never silently repair sequences.
- Delay must be an integer from 1 through 9999 milliseconds.
- Text permits printable ASCII, tab, newline, and carriage return. Reject non-ASCII and reserved control bytes, notably NUL and U+0001.
- Permit `raw` Launcher event tuples, preserving them exactly in generated JSON. Reject malformed or unencodable tuples; warn about known submit normalization/dropping, including raw Tap events. Raw events are the escape for unusual sequences, not a promise of exact firmware preservation.
- Calculate encoded buffer size, including slot terminators. Enforce `capacity_bytes` when supplied; otherwise report size and explicitly state that capacity is unverified.

## Outputs and fidelity boundary

- `npm run build` produces `dist/launcher.json`, plus `dist/macro.json` when macros are defined.
- Macro output is `{md5, macro, name}`: ordered slot arrays of Launcher event tuples and parallel names.
- Macro checksum is lowercase MD5 of `JSON.stringify(macro) + "875824192"`; names are excluded.
- Use nonempty display names for generated keyboard events so the current-slot editor accepts them.
- Validate all source data and references before writing outputs.
- Macro import loads editor state; submission is a separate human action. Launcher can normalize mouse events and drop raw tap events. Generated-import fidelity does not establish exact firmware-buffer fidelity or hardware execution.
- Preserve the established keymap checksum and raw-data contract. Broader settings remain outside both outputs.

## Verification

- Migrate independent fixtures to source v2; do not tie historic migration expectations to the user's editable keymap.
- Test readable and raw combinations, uniqueness, field translation, names, restrictions, and preservation.
- Test macro event expansion, byte representability, checksums, slot padding, capacity, text safety, held-key checks, raw-event preservation/warnings, and cross-references.
- Check deterministic offline builds and that adding the gateway combination leaves unrelated bindings/raw data unchanged.
- Human follow-up: import and test gateway access from every visible layer. Later test an intended macro through import and submission; static evidence is not hardware verification.

## Observed Launcher name-display pitfall

On 2026-11-03, the user reported that the imported `03+04` combination appeared
with a blank label, although the generated file contained
`simultNames: {"0304": "Gateway"}`. After renaming it in Launcher, the user's
`TrackballKeymap-Nape Pro-2026-11-03.json` export contained
`simultNames: {"0304": "gateway"}`. Its keymap, knob, tap/hold, combination
records, and checksum matched the generated data.

This confirms name export preservation, not reliable name display after import.
Keep name support and the source name; a UI rename is a display workaround, not
a change to the authoritative source. The import/display cause is unresolved.
Checksum equality alone cannot verify names because `simultNames` is not hashed.

## Static macro evidence

The saved main bundle `inspection/Keychron Launcher_files/main.f6e30fd5066dd94a.js`
selects module 44040's `xV` enum for protocol 12 in module 13814. The canonical
single-byte map is pinned in `data/launcher-macro-keycodes.json`; missing enum
values must not be inferred from generic HID numbers. `KC_CLR` is a verified
forward alias for decoder-canonical `KC_CLEAR` at byte 156.

Module 81617's `toMacroBufForV11` encodes keyboard tuples as three bytes,
delays as `[1,4,...decimal ASCII,124]`, text as character bytes, and one zero
terminator per slot. Module 58618's Nape writer checks payload length against
capacity; its final-capacity marker is not an extra codec byte.

Active Nape macro page module 85144 in
<https://launcher.keychron.com/144.fcdf2a230aca0a0e.js> exports
`{md5, macro, name}` and loads it into editor state on import. Submission keeps
down/up/delay/text, drops Tap tuples, and expands mouse editor tuples. The
independent fixture `test/fixtures/macro-export.json` captures the verified tuple
shape and checksum; it is not a hardware-read fixture.
